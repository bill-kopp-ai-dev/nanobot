## 2. Bloqueios para P4

P4 inclui F4 (restore/rollback aceitação), F5 (CI remota) e a fixação dos SHAs candidatos. As ações dependem de:

- **`gh auth login` na sessão do operador.** Sem isso, `gh run list`, `gh workflow run` e `gh run download` não funcionam. O [plano de fechamento F4/F5](../plans/2026-10-10-f4-f5-closure-plan.md) já propôs a sequência; este pacote não duplica nem inicia mutações.
- **Decisão de promover pins de runtime para os SHAs candidatos.** Cinco dos seis pins ativos ainda correspondem a SHAs anteriores ao HEAD atual (Notes é o único bate). A promoção exige rebuild + canary + retenção do último bom; sem isso, F4 não fecha.
- **OpenSSH Forky build/teste** (pendência #11) ou waiver individual aprovado. Sem fix ou waiver, o gate F3 não fecha.
- **OpenVEX aplicável aos demais digests.** O VEX atual é restrito ao image ID do gateway; estender automaticamente aos MCPs seria presunçoso.

## 3. Bloqueios para P5

P5 é o aceite VPS e a assinatura F7. As ações dependem de:

- **Acesso ao host VPS via SSH.** O ambiente desta sessão não tem `nc`, host ou credenciais. O [plano MCP Docker first-class](../plans/2026-10-06-mcp-docker-first-class-execution-plan.md) já estabelece os gates VPS (Engine 27.x, mounts, UID/GID, token, restore/journal, etc.) e o [runbook F5](../mcp-docker-f5-runbook.md) cobre a migração de estado.
- **Decisão B6/B7 (ensaio/cutover do operador).** O [governance B13](../percival-governance.md#b13-release-authority) reserva esses passos ao operador; o agente não os inicia.
- **B13 release authority.** A aprovação final de tag/publicação no SHA candidato é ato separado e exige operador com credencial pública. Sem `gh auth` e sem decisão de release, este pacote não declara release.

## 4. Ações executadas nesta sessão e limites

## 5. Como destravar

| Bloqueio | Ação do operador | Sequência agente após destravar |
| --- | --- | --- |
| `gh` | `gh auth login --with-token` (ou `gh auth login` interativo) na sessão do operador. | Disparar workflows nos SHAs candidatos dos sete repos; baixar artefatos manifest/SBOM; confrontar com a fonte; atualizar [relatório F5](../reports/2026-10-09-f5-ci-conformance.md) e o [relatório F4/F5](../reports/2026-10-10-f4-f5-closure-report.md). |
| VPS | Confirmar host/credenciais em janela autorizada. | Executar `scripts/percival-vps-inventory.sh`; validar Engine, mounts, GIDs, token; aplicar os gates do [plano MCP Docker first-class](../plans/2026-10-06-mcp-docker-first-class-execution-plan.md) e o [runbook F5](../mcp-docker-f5-runbook.md). |
| OpenSSH Forky | Autorizar o build ou waiver individual. | Build do gateway em base Forky, regressão Percival Remote SSH, novos scans Trivy/SBOM, atualização do VEX. |
| Khan allowlist | Decidir leitura/escrita/subset e autorizar `update-image`/`configure` com CAS. | Aplicar por gestor; verificar `tools/list`; atualizar ADR. |
| Credencial operator-admin | Rotação via interface suportada. | Verificar autenticação com a credencial nova; continuar apenas com o que a P0 não cobre. |

Nada nessas linhas é executado sem autorização explícita e por canal suportado.
